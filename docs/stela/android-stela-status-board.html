⛔ What we need from backend

Missing routes or data — split by when we need it

  • Blocks the flag flip (VSP-1778 · Private Files only)
  • Pending shares-to-archives in children shares[] — folder items onlyBlocked

    Refined + live-verified on staging 2026-07-31 (one children capture): record items already include pending shares (get_records.sql keeps everything but deleted — record faux-potted-cactus returned its status.generic.pending share); folder items drop them (get_folders.sql filters to status.generic.ok — the Vacation folder still omits pending shareId 2010). One-line backend fix: align the folder filter with the record one. The Android mapper already handles pending entries in shares[], so no app change needed. Still the one thing to fix before the production flag flip.

  • Findings for future tickets — not scheduled yet
  • Caller accessRole + complete shares[] on shared-tree childrenBlocked

    Blocks Shared With Me drill-in (its own ticket, pending this): items inside a foreign shared folder carry no share data on V2, so their options menus can't derive permissions — and the bearer-only call can't carry share membership at all. Shared By Me shipped without it (VSP-1803): own-archive content derives permissions from the archive-level role (CurrentArchivePermissionsManager), stamped client-side. The iOS team already requested this from the backend (priority 2 on their asks list); one theme with the badge row above.

  • Folder creationBlocked
    POST /v2/folders — does not exist

    Verified in stela docs + iOS PR #573. Stays on V1 folder/post; blocks the VSP-1778 follow-up ticket.

  • Relocate · copy · move · deleteBlocked

    No V2 routes. V1 writes key on folder_linkId + archiveNbr — why V2 children must keep shipping both.

  • Uploads (presigned + register)Blocked

    No V2 route; only coupling to navigation is the post-upload refresh (covered by VSP-1778).

  • Search query (search/folderAndRecord)Blocked

    No V2 route (neither platform has one). Drill-in from a search result is migrated (VSP-1806, left column) — only the query call itself stays V1.

  • Shares root list (getShares)Blocked

    No V2 route (iOS's proposed GET /v2/shares?direction=… was never built). Drill-in from a Shared By Me row is migrated (VSP-1803, left column) — only the root listing call stays V1. Pre-existing quirk noted during VSP-1803: the root listing only delivers non-empty lists, so a refresh returning zero shares leaves a stale list (separate ticket candidate).

  • 401 reserved for expired/invalid tokens (403 for permission denials)Blocked

    Needed before the V1 sunset: session expiry is detected only on the V1 host today (UnauthorizedInterceptor), which is what lets V2 401s degrade to the V1 failsafe — once V1 is gone, an expired session would never log out. The app-side fix is already implemented dark behind FeatureFlags.treatStelaUnauthorizedAsSessionExpiry (OFF in every build, 2026-08-13); flipping it requires the backend to stop answering 401 for bearer-only permission denials (known counterexample: iOS PR #576's PATCH /api/v2/records/{id} on a shared-with-me record). Full write-up: contract doc, gap 7.

  • Reliable paginationBlocked

    nextCursor non-null on complete pages, totalPages wrong — blocks the real cursor-paging ticket; until then both platforms fetch one huge page.

  • Link-address resolution (V1 link ids → V2 ids)Blocked

    All workspaces swept (2026-08-11): the app mints/consumes exactly two link families — public URLs (/p/archive/…) and share links (/share/{token}) — and they carry V1-era addresses that four V2 lookups can't do: folder_linkId → folderId (folder links), record archiveNbr → recordId (record links), share token → shareLinkId (V2 share-links accepts only shareLinkIds[]; today learned via V1 share/getLink), and archiveNbr → public root folderId (entry point of every public link; today V1 getPublicRoot). Deep links are the same two families, not a separate case; archive profile links unaffected. Ranked asks (VSP-1810 comment, 2026-08-06): (1) a V2 resolver family covering all four, (2) V1-era keys as alternative addresses on existing V2 routes, (3) ids in the URL format (still needs 1/2 for old links). Nothing broken today — V1 fallbacks work — but every shared link keeps V1 alive. Full inventory: docs/stela-v2-link-migration.md.
